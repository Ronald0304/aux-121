# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Frontend en HTML, CSS y JavaScript sin framework. Backend Node.js + Express con SQLite (better-sqlite3). Elegido por el usuario.

## Users

Dueño: Ronald Gutiérrez Mamani, estudiante de la Licenciatura en Informática (UMSA, La Paz, Bolivia), enfocado en desarrollo web.
- Reclutadores, líderes técnicos y clientes potenciales que evalúan a un desarrollador full-stack en pocos minutos, normalmente desde un enlace en un CV, LinkedIn o un correo.
- El propio dueño del portfolio, que mantiene el contenido desde un panel admin.

## Product Purpose

Portfolio personal de un desarrollador full-stack. Muestra proyectos, experiencia y habilidades cargados desde una base SQLite, permite contactar (mensajes guardados en la BD), dejar una firma en un libro de visitas y aplaudir proyectos. Éxito: el visitante entiende qué construye esta persona y le escribe.

## Positioning

El propio portfolio es una pieza full-stack funcionando: front, API y base de datos que el visitante usa en vivo (aplausos, libro de visitas, contacto), no solo una galería de capturas.

## Capabilities and Constraints

- Proyectos, experiencia y skills servidos por API desde SQLite.
- Formulario de contacto que guarda en SQLite.
- Comentarios (libro de visitas) y "me gusta" por proyecto.
- Panel admin protegido con contraseña: ver mensajes, moderar el libro, crear/editar/borrar proyectos.
- Nombre real, foto y proyectos reales del dueño: **sin decidir**. El contenido inicial es de ejemplo (sintético) y se reemplaza desde el seed o el admin.

## Brand Commitments

Diseño fijado por el usuario: el prompt "experiments-gallery" de motionsites.ai (galería WebGL curva, lente de vidrio, luces RGB en el borde), todo en español. Sin usar los recursos de imagen y video de terceros del prompt original.

## Evidence on Hand

Ninguna todavía. No inventar empresas reales, clientes, métricas ni testimonios presentados como reales; todo el contenido de ejemplo queda marcado como editable.

## Product Principles

1. El sitio demuestra la habilidad que anuncia: todo lo dinámico funciona de verdad.
2. Contenido primero: el trabajo lidera, la interfaz se retira.
3. Fácil de mantener: cambiar contenido nunca requiere tocar HTML.
4. Rápido y accesible sin dependencias de frontend.
